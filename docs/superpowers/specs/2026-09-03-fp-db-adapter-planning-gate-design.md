# fp-db-adapter 自动判定与方案确认设计

## 背景

`fp-db-adapter` 当前将任务分为“迁移报错定位”和“单纯适配”，能够处理达梦与 OceanBase 的配置、依赖、迁移补丁、SQL/ORM 和蓝鲸包配置，但不能稳定区分全新适配与增量适配，也没有阻止方案确认前修改项目文件。

本次调整将 skill 改造成“先扫描和确认方案，再实施和验证”的两阶段工作流。Skill 自动判断适配阶段与数据库范围，并把判断证据、计划修改位置、代码变化和验证方法完整展示给用户。

## 目标

- 自动判断当前任务属于全新适配还是增量适配。
- 自动判断适配范围是仅达梦、仅 OceanBase，还是全量数据库。
- 将“全量数据库”严格定义为同时适配达梦和 OceanBase，不扩展到其他数据库。
- 在用户确认前只读取和分析项目，不修改项目文件。
- 输出精确到文件、当前行号、稳定代码锚点和计划代码片段的详细方案。
- 用户确认后只实施已确认范围；发生实质性方案漂移时重新确认。
- 实施后提供可追溯的修改总结、验证结果和未验证事项。

## 非目标

- 不增加人大金仓、瀚高、GaussDB 等数据库支持。
- 不要求仅凭静态扫描保证目标数据库运行成功。
- 不为没有证据表明存在兼容问题的 migration 批量创建补丁。
- 不在本次调整中实现独立扫描脚本或数据库连接工具。

## 工作流

### 阶段一：扫描与方案

每次适配任务默认从阶段一开始。Skill 可以读取代码、配置、迁移、依赖、Git 状态和用户提供的日志，也可以执行不会写入项目的检查命令，但不得编辑、创建、删除或格式化项目文件。

阶段一按以下顺序执行：

1. 识别 Django/Python、配置入口、依赖管理方式、项目类型和已有数据库能力。
2. 判断全新适配或增量适配。
3. 判断达梦、OceanBase 或全量数据库范围。
4. 按选定范围扫描配置、依赖、migration、迁移补丁、SQL/ORM 和包配置。
5. 输出详细适配方案和总结。
6. 明确请求用户确认并停止，不在同一轮继续实施。

### 阶段二：实施与验证

只有用户在看到当前方案后明确表达“确认”“按方案执行”“确认实施”等意思，才进入阶段二。一般问答、补充日志、修改要求或对局部内容的认可不构成实施授权。

阶段二必须：

1. 只实施已确认方案中的文件和范围。
2. 保留用户在确认后新增的约束。
3. 执行方案约定的静态检查和可用的目标库验证。
4. 输出实际修改总结，并说明与方案是否一致。

以下变化属于实质性方案漂移，必须暂停实施、补充方案并重新请求确认：

- 需要修改或新增方案未列出的项目文件。
- 需要删除外键、唯一约束、索引或其他业务约束。
- 需要修改已执行的原始 migration，而不是使用项目认可的补丁或后续 migration 机制。
- 数据库范围从单库扩展到全量，或从一种数据库切换到另一种。
- 需要改变依赖主版本或替换数据库基础设施。
- 发现方案中的核心判断错误，导致实现方式或风险等级明显变化。

仅行号变化、格式化引起的位置移动，或同一代码锚点内不改变行为的小调整不属于实质性漂移，但必须在实施总结中说明。

## 适配类型判定

### 全新适配

当项目整体缺少目标数据库能力，且任务是首次接入时，判定为全新适配。主要证据包括：

- 不存在达梦或 OceanBase 的 `DATABASE_TYPE` / `DATABASES` 分支。
- 未注册 `cw_cornerstone.migrate_patch` 或项目等价的迁移补丁机制。
- 不存在目标数据库迁移补丁目录。
- 依赖中不存在目标数据库 backend 或驱动。
- 用户明确说明是新 SaaS、首次接入或从未做过信创适配。

并非所有证据都必须同时满足。Skill 应综合代码事实和用户表述说明判定依据。

### 增量适配

出现以下任一强证据时，通常判定为增量适配：

- 已存在达梦或 OceanBase 配置。
- 已注册迁移补丁机制或存在目标数据库迁移补丁。
- 用户提供现有适配后的 migration 或运行报错。
- 用户要求补充、修复、升级、完善或审查已有适配。

当证据冲突时，优先判定为增量适配，以保护已有实现和迁移历史。若扫描后仍无法可靠区分，Skill 只询问一个能决定分支的关键问题，在得到答案前不输出假定为确定事实的方案。

## 数据库范围判定

支持范围固定为：

- `dameng`：仅达梦。
- `oceanbase`：仅 OceanBase。
- `all`：达梦和 OceanBase。

判定优先级如下：

1. 用户明确指定的数据库范围优先。
2. 报错日志明确来自一个数据库时，默认仅处理该数据库。
3. “全量适配”“全部适配”“全库适配”表示 `all`。
4. 用户只说“信创适配”且未指定范围时，根据项目现状提出推荐范围：两者都缺失时推荐 `all`；仅缺一方时推荐缺失的一方；已有双方能力时根据发现的问题确定范围。
5. 推断得到的范围必须写入方案并等待确认，不能把推荐范围视为已授权实施范围。

## 扫描范围

Skill 根据实际项目结构定位文件，不硬编码要求每个项目都具备相同路径。扫描至少覆盖：

- Django settings 及环境配置入口。
- `INSTALLED_APPS`、`DEFAULT_AUTO_FIELD`、`DATABASE_TYPE` 和 `DATABASES`。
- `requirements*.txt`、`pyproject.toml`、锁文件或其他实际依赖入口。
- 自研与相关第三方 app 的 migration。
- `migrate_patch/patches/dameng` 和 `migrate_patch/patches/oceanbase` 或项目等价目录。
- `RunSQL`、`RunPython`、raw SQL 和已知高风险 ORM。
- `app_desc.yaml`、架构拆分 YAML 或项目实际部署描述文件。
- 用户提供的错误日志和已有目标数据库验证结果。

AutoOps 或蓝鲸项目才读取并应用 `references/autoops-patterns.md`；普通 Django 项目不能无条件套用 AutoOps 的固定版本、配置路径和平台环境变量。

## 方案输出契约

阶段一的方案必须包含以下部分。

### 适配结论

- 适配类型：全新适配或增量适配。
- 数据库范围：达梦、OceanBase 或达梦 + OceanBase。
- 项目类型：通用 Django、蓝鲸 SaaS、AutoOps 或实际识别结果。
- 判断依据：引用扫描到的文件、配置和日志事实。
- 判断置信度：确定或待确认；待确认时说明缺少的唯一关键信息。

### 当前状态总结

- 已具备的数据库能力。
- 缺失或不完整的能力。
- 已有适配内容及可复用模式。
- 主要兼容、迁移和部署风险。
- 是否具备目标数据库连接和验证条件。

### 文件级修改方案

每个计划修改或新建的文件必须单独列出：

- 文件路径。
- 修改类型：新建、修改或删除；删除应极少使用并明确原因。
- 当前位置：当前真实行号和稳定代码锚点，例如函数名、配置项、migration operation。
- 当前代码：只展示相关代码块；新文件标记为不存在。
- 计划代码：展示预期代码块或结构。若内容依赖实施时生成的信息，明确说明生成规则，不编造代码。
- 修改原因和对应数据库。
- 行为影响与风险。
- 验证方式。

行号来自扫描时的文件状态，并与稳定代码锚点配合使用。新文件写“文件不存在，计划新建”，可标注“预计从第 1 行开始”，不得编造尚不存在的精确行号。实施后的行号变化不使已确认方案失效，代码锚点和行为范围才是主要标识。

### 迁移补丁方案

对每个计划新增或修改的 migration，说明：

- 原 migration 路径和补丁路径。
- 命中的兼容问题。
- 保留的 `dependencies` 和业务语义。
- 计划调整的 operation。
- 是否涉及已执行 migration。
- 回滚、幂等、数据量或锁表风险。

### 验证方案

区分并列出：

- 语法、导入和 Django system check。
- migration graph、`makemigrations --check` 和 migrate plan。
- 达梦空库或增量迁移验证。
- OceanBase 空库或增量迁移验证。
- 核心业务读写与约束验证。
- 当前环境无法执行的验证及原因。

### 方案总结与确认提示

结尾汇总计划修改文件数、新增补丁数、数据库范围、主要风险和预计验证层级，并明确说明当前未修改项目文件。随后请求用户确认、调整或取消方案。

## 实施总结契约

阶段二完成后必须输出：

- 最终适配类型和数据库范围。
- 实际修改和新建的文件。
- 每个文件修改后的真实行号及稳定代码锚点。
- 每个 migration 命中的适配点。
- 方案与实际实施的差异；无差异时明确写明。
- 已执行验证命令及逐项结果。
- 静态验证和目标库实连验证的明确区分。
- 未验证事项、遗留风险和上线注意事项。

不得将静态检查、migrate plan 或代码审查描述为目标数据库实连通过。

## 验收场景

### 全新 SaaS，未指定数据库

项目只有 MySQL 配置且没有补丁机制。Skill 应判定为全新适配，推荐 `all`，输出达梦和 OceanBase 的文件级方案并等待确认，不修改代码。

### 已适配达梦，要求信创适配

项目已有达梦配置和补丁，但没有 OceanBase。Skill 应判定为增量适配，推荐仅 OceanBase，说明判定证据并等待确认。

### OceanBase migration 报错

日志明确来自 OceanBase。Skill 应判定为增量适配、单库 OceanBase，定位失败 migration，输出最小补丁方案并等待确认。

### 用户明确要求全量适配

无论项目当前状态如何，数据库范围均为达梦 + OceanBase；适配类型仍由项目事实判断。

### 实施中发现新增范围

用户确认方案后，若发现必须修改未列出的依赖文件或删除业务约束，Skill 应停止修改并输出补充方案，等待再次确认。

### 仅讨论或补充信息

用户对方案提问或补充日志时，Skill 不得视为实施确认，应更新分析或方案后继续等待明确授权。
