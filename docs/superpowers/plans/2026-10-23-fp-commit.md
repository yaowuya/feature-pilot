# fp-commit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This session executes inline; do not commit, push, or merge this plugin repository unless the user separately requests it.

**Goal:** Add a public FeaturePilot commit workflow that reviews against initialized code standards, repairs findings, commits and pushes, and optionally creates or merges a PR/MR; explicit `auto` ends after creating a PR/MR to the verified default branch.

**Architecture:** `fp-init` owns optional project rules document creation/registration. `fp-commit` owns review and narrowly updating an already registered project rules document, then Git/PR orchestration. Shared `engineering-quality.md` remains the rules-consumption entry; the thin command and routers only discover the new skill.

**Tech Stack:** Markdown skills/commands, PowerShell 5-compatible static contract validators, Git CLI, host-specific GitHub/GitLab PR/MR tools when available.

## Global Constraints

- The agreed behavior is in `docs/superpowers/specs/2026-10-23-fp-commit-design.md`; no automatic merge in `auto`.
- `fp-commit auto` must be explicit per run; Claude/host permission mode never enables it implicitly.
- New rules are project-specific. Plugin-wide `common.md`, `django.md`, and `vue.md` remain unchanged.
- Keep `fp-init` manifest-only by default and require per-file approval for settings creation/registration.
- This implementation does not itself authorize committing, pushing, creating PRs, or merging changes in this repository.
