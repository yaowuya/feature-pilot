# 信创数据库适配

自动识别项目现状和用户目标，规划并实施达梦、OceanBase 或两者的数据库适配。保留项目已有模式和迁移历史，不把静态推断描述为目标库验证结果。

## 不可跳过的两阶段门禁

每次任务都从阶段一开始。即使用户在首次请求中说“直接修改”或“自动执行”，也先完成扫描、输出方案并停止；只有用户看到当前完整方案后明确确认，才能进入阶段二。

### 阶段一：扫描与方案

- 只读取和分析项目、Git 状态及用户日志；不编辑、创建、删除或格式化项目文件。
- 自动判断适配类型、数据库范围和项目类型，并列出实际证据。
- 按 `references/adaptation-scope.md` 的固定检查分组和顺序逐项扫描；一次完成全部只读检查，不在分组之间请求确认。
- 每项立即输出编号、固定状态、证据、判断依据和处置结论；即使整个分组不适用，也保留该分组并说明跳过原因。
- 全部检查完成后汇总未适配项，输出文件级详细方案和总结，然后只请求一次统一确认并结束当前轮。

### 阶段二：实施与验证

- “确认”“按方案执行”“确认实施”等针对当前完整方案的明确授权，才可进入本阶段。
- 提问、补充日志、修改要求、只认可局部内容或首次请求中的预授权，均不视为确认。
- 只实施已确认的文件和数据库范围，并执行方案中的验证。
- 复用阶段一的检查项编号逐项实施和报告进度；不得修改标记为已适配或不适用的项目。
- 完成后输出实际修改总结、验证结果和未验证事项。

出现以下实质性方案漂移时，立即停止，输出补充方案并重新请求确认：

- 需要修改或新增当前方案未列出的项目文件。
- 需要删除外键、唯一约束、索引或其他业务约束。
- 需要修改已执行的原始 migration，而不是使用项目认可的补丁或后续 migration 机制。
- 需要改变数据库范围。
- 需要改变依赖主版本或替换数据库基础设施。
- 核心判断发生变化，导致实现方式或风险等级明显改变。

行号变化、格式化引起的位置移动，或同一代码锚点内不改变行为的小调整，不属于实质性漂移，但要在实施总结中说明。

## 自动判定

### 适配类型

判定为**全新适配**时，项目应整体缺少所选目标数据库能力，且任务是首次接入。综合检查：

- 是否缺少目标数据库的 `DATABASE_TYPE` 或 `DATABASES` 分支。
- 是否未注册 `cw_cornerstone.migrate_patch` 或项目等价机制。
- 是否不存在目标数据库迁移补丁目录。
- 是否缺少目标数据库 backend 或驱动依赖。
- 用户是否明确说明是新 SaaS、首次接入或从未适配。

出现任一强证据时，通常判定为**增量适配**：

- 已存在达梦或 OceanBase 配置、补丁机制或补丁文件。
- 用户提供已有适配后的 migration 或运行报错。
- 用户要求补充、修复、升级、完善或审查已有适配。

证据冲突时优先判定为增量适配，以保护已有实现和迁移历史。必须在方案中引用具体文件、配置或日志作为依据。仍无法可靠判断时，只询问一个能决定分支的关键问题，不把推断写成确定事实。

### 数据库范围

仅支持以下范围：

- `dameng`：仅达梦。
- `oceanbase`：仅 OceanBase。
- `all`：达梦 + OceanBase，即本技能所称“全量数据库”。

按以下优先级判断：

1. 用户明确指定的数据库范围优先。
2. 报错日志明确来自一个数据库时，默认仅处理该数据库。
3. 用户说“全量适配”“全部适配”或“全库适配”时，范围为 `all`。
4. 用户只说“信创适配”且未指定范围时，根据项目缺口提出推荐：两者都缺失时推荐 `all`；仅缺一方时推荐缺失的一方；已有双方能力时根据实际问题确定。

推断或推荐的范围必须写入方案并等待确认，不能视为已经获得实施授权。不得自动扩展到人大金仓、瀚高、GaussDB 等未支持数据库。

## 扫描与参考路由

- 全新或增量适配审计时，读取 `references/adaptation-scope.md`。
- 涉及 migration 扫描、报错或补丁时，读取 `references/compatibility-checklist.md`。
- 仅在代码或用户信息确认项目是 AutoOps、蓝鲸 SaaS，或采用同类 `cw_cornerstone` 约定时，读取 `references/autoops-patterns.md`。普通 Django 项目不得套用其中固定版本、配置路径和平台变量。
- 日志不完整时，先说明缺失信息；仍可静态定位，但将结论标为“基于静态推断”。

## 固定检查状态

每个检查项只能使用以下状态之一，不得省略已适配或不适用的项目：

- `[已适配，跳过]`：有充分证据证明目标能力已适配，明确输出“<检查项> 已适配，跳过”。
- `[需要适配]`：确认能力缺失或当前实现不兼容，纳入适配方案。
- `[待验证]`：静态扫描无法证明兼容或风险较高，纳入验证方案。
- `[不适用，跳过]`：不属于当前项目、适配类型或数据库范围，说明原因后跳过。
- `[无法判断]`：缺少必要代码、配置或环境信息，列出需要补充的内容。

不能仅凭文件名、注释、目录存在或依赖声明判定为已适配。必须引用能证明实际注册、配置、执行路径或验证结果的证据；证据不足时使用 `[待验证]` 或 `[无法判断]`。

每个检查项至少输出：

- 检查项编号和名称。
- 固定状态及明确结论。
- 文件路径和扫描时的当前行号（存在文件证据时）。
- 稳定代码锚点（存在代码证据时）。
- 判断依据或扫描发现。
- 后续处置：跳过、纳入适配方案、纳入验证方案或等待补充信息。

输出形式示例：

```markdown
- [已适配，跳过] 3.1 达梦数据库驱动已适配，跳过
  - 证据：requirements/base.txt:42
  - 锚点：dmPython==2.5.5
  - 处置：无需修改

- [需要适配] 3.2 OceanBase 数据库后端尚未适配
  - 证据：settings/database.py:86
  - 锚点：DATABASE_ENGINES = {
  - 发现：仅存在 MySQL 和达梦配置分支
  - 处置：纳入适配方案
```

## 阶段一输出契约

方案必须包含以下部分。

### 适配结论

- 适配类型：全新适配或增量适配。
- 数据库范围：达梦、OceanBase 或达梦 + OceanBase。
- 项目类型：通用 Django、蓝鲸 SaaS、AutoOps 或实际识别结果。
- 判断依据：扫描到的文件、配置和日志事实。
- 判断置信度：确定或待确认；待确认时说明缺少的唯一关键信息。

### 当前状态总结

说明已具备能力、缺失能力、可复用的已有适配、主要风险，以及是否具备目标数据库连接和验证条件。

### 固定检查分组与逐项结果

严格按照 `references/adaptation-scope.md` 中的十个分组和检查项顺序输出。适配范围为 `all` 时，达梦与 OceanBase 分别判定；一方已适配不能代替另一方的结论。

### 文件级修改方案

每个计划修改或新建的文件必须单独列出：

- 文件路径和修改类型：新建、修改或删除。
- 当前位置：扫描时的真实行号和稳定代码锚点，如函数、配置项或 migration operation。
- 当前代码：只展示相关代码块；文件不存在时写“文件不存在，计划新建”。
- 计划代码：展示预期代码块；若依赖实施时信息，写明确定的生成规则，不编造代码。
- 修改原因和对应数据库。
- 行为影响、风险和验证方式。
- 对应检查项编号、所属分组、执行顺序和前后依赖。

新文件可写“预计从第 1 行开始”，不得编造不存在的精确行号。行号用于辅助定位，稳定代码锚点和行为范围是实施时的主要标识。

### 迁移补丁方案

存在 migration 改动时，逐项说明原 migration、补丁路径、兼容问题、保留的 `dependencies` 与业务语义、计划调整的 operation、是否涉及已执行 migration，以及回滚、幂等、数据量和锁表风险。

### 验证方案

区分语法和 Django 检查、migration graph 与 plan、达梦实连、OceanBase 实连、核心业务读写和当前环境无法执行的验证。适配 `all` 时分别列出两种数据库的验证，不用一方结果代替另一方。

### 方案总结与确认

汇总检查项总数、已适配并跳过数量、需要适配数量、待验证数量、不适用并跳过数量、无法判断数量，以及计划修改文件数、新增补丁数、适配类型、数据库范围、执行顺序、主要风险和预计验证层级。

若 `[无法判断]` 缺失的信息会影响方案正确性或实施范围，先请求补充信息，不得请求实施确认。信息完整时，明确输出“等待用户确认方案”，说明当前未修改项目文件，然后请求用户对完整方案确认、调整或取消。输出后停止，不在同一轮进入实施。

## 阶段二输出契约

实施完成后必须说明：

- 最终适配类型和数据库范围。
- 实际修改及新建文件，以及修改后的真实行号和稳定代码锚点。
- 每个 migration 命中的适配点。
- 方案与实际实施的差异；无差异时明确说明。
- 已执行的验证命令和逐项结果。
- 静态验证与目标库实连验证的区别；没有真实目标库时写明“未做目标库实连验证”。
- 未验证事项、遗留风险和上线注意事项。

实施期间复用检查项编号并即时报告，例如：

```text
[3.2 实施中] OceanBase 数据库后端配置
[3.2 已完成] OceanBase 数据库后端配置
[5.3 验证失败] Migration 字段类型转换
```

最终总结将每个已确认计划项映射到实际变更及验证结果。

不得将静态检查、migrate plan 或代码审查描述为目标数据库实连通过。
