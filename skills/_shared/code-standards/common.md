# 公共代码质量规范

这是已登记 Django / Vue 内置规范的公共入口。按 [工程质量契约](../engineering-quality.md) 解析 settings、适用端和客户覆盖；本文件只维护 Q01–Q05，共享注释与复杂度要求仍由该契约维护。未标注【建议】的条款为【必须】。

## Q01 — 适用范围与读取入口

- 技术设计、规划、开发、自检、获授权的 Commit 和 Review 使用本规范；根据当前变更显式读取已登记的 [Django 规范](django.md) 或 [Vue 规范](vue.md)，跨端读取两份，不因本入口有链接就加载无关端。
- 只约束本次新增和实质修改的代码及受影响调用链，不强制改写无关存量、第三方、生成文件或已执行迁移。因本次变更触发的存量缺陷仍需检查。
- 实现事实由当前源码、依赖、配置核对；目标要求由当前用户指令、客户明确规范和已批准需求核对。源码可以反证事实，不能自动取消已确认的目标规范；冲突先报告，不杜撰基类、库或能力。
- 例外记录规则编号、实际适用条件、原因和影响；“仓库已有类似写法”不单独构成例外。客户明确覆盖优先；【建议】不单独阻断提交。

## Q02 — 双轨检查与证据

按完整相关 diff 及受影响调用链分别报告：

1. **规范符合性**：规则编号、path:line、实际偏差及修正方式。已确认的规范违反即使没有运行时故障，也保留在此维度。
2. **代码缺陷**：具体输入/状态 → 错误结果、影响、根因、验证证据与修复建议；只报告当前变更新增或触发、已验证且值得处理的问题。

- 同一根因只计一次，规范项可引用对应缺陷。纯命名/风格偏差不伪装为 medium/high 功能缺陷或行内缺陷评论，必要修正保留在规范总结中。
- 按主题记录“通过 / 违规 / 不适用 / 未验证”，不适用写原因。历史问题、未确认候选和环境阻塞分别归类，不伪装成当前 diff 的已验证缺陷。
- 工具、目标库、权限或环境不足时写明缺口；源码阅读、mock 和文档更新不等于真实环境运行通过。

## Q03 — Commit 前置检查

- 仅在用户已授权提交时执行 Commit 流程；识别实际提交范围和需求，完成 Q02 双轨自检与适用验证。当前新增的必须项违规或已确认缺陷先修复，明确接受的例外记录影响；敏感信息与未授权操作仍须停止。
- 按具体文件暂存，检查最终暂存快照：`git diff --cached --stat`、`git diff --cached`、`git diff --cached --check`。部分暂存时验证实际代码组合，工作区测试不自动证明暂存版本。
- 格式化、hook 或再编辑改变已检快照时，复查受影响 diff、重跑必要验证并重新暂存；快照未变且证据有效时复用，不机械全仓重测。
- 提交前报告规范、缺陷、验证结果及未验证项；必要验证无法完成时先取得对该缺口的明确确认。hook 失败先调查，不自行 `--no-verify` 或跳过检查。
- 提交授权不包含 push、PR/MR、发布评论或部署；流程和产物位置服从当前技能与项目授权边界。

## Q04 — Review 范围与结论

- 固定审查快照：工作区/暂存区分别说明，分支记录 Base/Head，PR/MR 使用对应远端 Base/Head，不以当前 checkout 冒充远端版本。
- 覆盖范围内业务代码、测试、迁移、权限、依赖和配置；需要时读取未修改调用方或公共实现验证影响，不静默缩小到易查部分。
- 同时说明规范违规、已验证缺陷与未验证项；“无已验证代码缺陷”不代表规范通过。必须项违反应建议修正后提交/合并，但不编造失败场景或严重度。
- 默认只读，未获授权不修改、提交、推送或发布。Review 的严重度、报告形状和重试沿用当前技能；Head 变化后旧结论不能直接用于新快照。

## Q05 — 验证与改动控制

- 命令从实际项目配置选取，限定相关文件/模块。修复覆盖复现回归，功能覆盖正常与负向路径；mock 隔离外部边界，不替换需要证明的核心行为。
- 静态/格式检查、单测、集成、浏览器和目标环境验证分别记录，一项通过不概括为全仓通过、部署完成或已上线。
- 执行前核对共享数据库、缓存、任务队列、外部 API 和真实业务代理；采用隔离环境/合成数据。未批准不安装依赖、执行迁移或真实业务操作。
- 检查脚本是否含 `--fix` 等写行为；改写后重审 diff，只读 Review 使用已证明的非修复模式。报告和临时文件遵循当前流程目录所有权。
- 不扩大为全仓格式化、框架升级或无关重构；保留用户既有改动，只暂存当前获授权内容。

报告结构沿用当前技能，在已有栏目中区分范围、规范、缺陷、验证和结论，不另建第二份报告或流程产物。本规范**不是 Git 自动门禁**，不会拦截手工 Git；Hook/CI 须独立授权、配置和验证。
