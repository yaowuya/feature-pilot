# Django 后端代码质量规范

配合 [公共规范](common.md) 使用，未标注【建议】的条款为【必须】。按 settings 的 appRoot、实际版本、客户规则和当前任务限定适用范围。DRF、Pydantic、Celery、软删除、多租户等细则仅在项目实际使用或当前需求明确批准引入时适用；采用规范不要求安装这些依赖或新建分层。

## B01 — 分层与公共能力

- 沿用已确认架构，HTTP 入口保持薄：参数/输入校验、权限入口、调用业务能力和构造响应；已有 Service 层负责复杂业务、查询、事务和外部 I/O，不把 HTTP Response 混入领域逻辑。
- DRF 的最小 `get_queryset()`、serializer/filter/pagination 声明可在 View；权限范围过滤本身不是分层违规。复杂聚合与状态变更归入现有业务边界，不为本规范制造空 Service/repository 层。
- entity/schema 负责数据结构与确定性校验，Serializer 负责表示转换，Model/Manager 承担持久化和必要框架协议；不向这些对象搬入外部工作流。
- 复用经核实的公共基类、工具和目录，检查继承的 create/update/destroy/action 是否绕过校验、权限、审计或业务边界。查询/授权上下文在请求运行时取得，不在导入或类级查询中执行 DB/外部调用。
- 复用前核对签名、返回与副作用，必要时隔离可变参数；少量重复不自动成为新增父类、Mixin 或通用框架的理由。

## B02 — 枚举、国际化与风格

- 枚举、`choices`、协议值与存储位置遵循客户已确认政策，不以本规范全局禁用 Django `choices` 或强制某个私有 BaseEnum；值变化检查存量数据、异步任务与 API 消费方。
- 用户可见文案使用项目翻译入口，Django 项目常用 `gettext_lazy`；保留可翻译占位符，协议字段名、机器码和英文日志标识不机械翻译。
- 命名采用 Python 惯例并遵循邻近代码；Black/isort/flake8/ruff 等工具和行长读取项目配置，不固定为 120，不为规范全仓格式化或安装工具。
- Python、Django 和 schema 库版本来自项目依赖及目标运行环境。Pydantic v1 使用其受支持 API；Pydantic v2 按 v2 API 与兼容边界实现，不混用两代 `dict`/`model_dump`、校验器和配置语义；本机解释器不构成升级授权。

## B03 — 输入校验与数据契约

- 写入口在业务处理前经过项目已有的 Form、DRF Serializer、Pydantic/entity 或等价校验入口；使用校验后数据，不重新读取原始 body 绕过校验，也不要求所有 Django 项目引入 Pydantic。
- 校验 query/path/body 中业务 ID、枚举、范围、长度、列表元素与批量上限；上传核对大小、类型、元数据和目标路径。无 body 的写操作校验实际 path/query，不制造空 schema。
- PATCH 区分未传、显式 `null` 与默认值；Pydantic v1/v2 分别使用支持的 `exclude_unset` 等语义。可变默认值使用 factory，不以默认配置覆盖真实配置。
- 操作者、授权范围和隔离上下文来自服务端可信身份；类型校验不替代存在性、权限、唯一性或状态机校验。输入/响应使用字段白名单，不泄露凭据、内部字段或整模型。
- 复用当前实际 Renderer/错误处理中间层，核对 HTTP 状态与业务 envelope，不双重包装、不把 HTTP 200 当业务成功。未知值不伪装为 0 或空数据，展示占位留给前端。
- 核对 schema、业务层、Serializer、前端及 API 文档的类型、日期、空值、分页和错误契约；接口变化同步项目现有 URL/网关/文档，不依赖特定外部技能，不把文档同步当联调通过。

## B04 — 模型、关联与软删除

- 先核对实际 Model/Manager、继承字段及框架协议，不假定存在某个租户基类，不重复声明基础字段。隔离通过真实字段、查询过滤、任务上下文及存储路径验证，基类名称不是证明。
- 按客户建模政策选择真实 `ForeignKey` 或逻辑 ID，不因规范强制互换。真实关系核对约束和删除策略；逻辑 ID 匹配来源类型并在业务边界批量校验存在性、权限和生命周期；可复用 code/name 不代替稳定 ID。
- 索引依据实际筛选/排序与目标数据库，避免重复索引。字段展示名遵循项目国际化约定，不为风格产生无关 migration。
- 使用软删除时核对默认 Manager、唯一性、历史引用、恢复和清理语义；绕过过滤的 Manager、原生 SQL、硬删除只在明确历史/回收语义和访问范围下使用。
- 并发唯一性依赖目标 DB 实际有效的约束，不只靠 `exists()` 后插入；检查软删除、NULL、首次创建及条件约束兼容性。
- JSON 默认值使用 callable，自定义字段按真实签名构造；大字段、编码和索引按目标数据库能力验证。

## B05 — ORM、批量与查询数量

- 逻辑 ID 关联先收集/去重并分批查询需要的字段，构建 map 供序列化使用；不在 SerializerMethodField、property、循环或序列化工具中引入隐式逐行查询。
- 仅对真实 ORM 关系使用 `select_related`/`prefetch_related`；预取、权限与聚合限定当前页/业务范围，不为小页面加载全表。
- 批量写核对 `bulk_create`/`bulk_update`/`update()` 绕过 save、signals、时间和业务钩子的影响，显式补齐必要操作者、审计和校验，并限制批次。
- 可合并 DB 操作不在循环执行；确有逐项锁、事务或信号语义时说明必要性和规模边界，不机械 bulk 改变行为。
- 只消费存在性/数量时用 `exists()`/`count()`；后续需要同批对象时避免重复查询。投影、聚合与 `iterator(chunk_size=...)` 按实际需求和 Django/预取兼容性使用。
- 先筛选排序再分页，排序稳定；大 IN、大文件、无界读取与逐条远端请求采用有界分批/流式/批量接口。【建议】新增列表聚合用查询数量测试证明不存在线性 N+1。

## B06 — 事务、并发与外部副作用

- 多步一致性写在现有业务边界内使用短 `transaction.atomic`，不把整个耗时入口机械包成事务。
- 事务内避免不可回滚/耗时外部 API、脚本、大文件和任务投递；先只读查询时在事务内复验关键状态。提交后动作用 `transaction.on_commit` 或已有可靠投递机制。
- `on_commit` 不是可靠队列，不能回滚已提交 DB；明确投递失败、重试、补偿和状态回查，强交付使用经确认的可靠方案，不虚称 DB/消息原子。
- `select_for_update()` 在 atomic 内，核对锁对象与顺序；首次创建无行可锁，仍需唯一约束/冲突处理。长任务回写前复验状态或版本。
- `IntegrityError` 在合适 savepoint/atomic 边界外捕获，识别真实约束冲突；不在已破坏的事务内继续查询。
- 分布式锁需要共享后端、owner token、安全释放与合理过期，进程内锁或本地缓存不证明跨 worker 互斥。任务重试幂等、有界、可超时，携带可信隔离上下文；撤销/重复调度不只靠前端防重。

## B07 — 权限、安全与审计

- 使用客户真实认证/资源/action 机制，分别验证 list/detail/create/update/delete/bulk、后台任务和默认继承路由；隐藏按钮或仅过滤列表不够。
- 读写前施加授权和实际隔离范围，检查猜 ID、跨租户/业务/分类及公共模型消费方；缓存限合理身份/请求范围，不以放开生产权限通过测试。
- 路径规范化并核对受管根、链接和解压逃逸；SQL 参数化，系统命令不拼接不可信输入，动态执行使用现有受控机制，不为调试绕过安全。
- 外部 client/adapter 设置超时，区分网络、协议与业务失败；有副作用请求不盲目重试，不返回假成功。
- 审计记录真实操作者、目标、结果与必要摘要，区分接受/完成/失败及事务阶段，不把回滚前记录宣称为成功。
- Cookie 会话保留 CSRF，403 区分会话/CSRF/授权。凭据、Token、Cookie、私钥不进入源码、URL、日志、异常或测试报告。

## B08 — 日志、异常与注释

- 外部调用在统一边界记录脱敏、截断的摘要、关联标识、耗时和失败类别；充分日志不在每层重复，不记录原始鉴权头、脚本或完整大响应。
- Python logging 使用延迟参数（如 `logger.info("id=%s", object_id)`），带业务/任务/request 上下文，避免预先格式化；结构化日志沿用已配置 logger 的真实 API。
- 日志级别区分故障、可恢复异常、状态变化与调试；堆栈按需记录，同一异常在负责处理的边界记录一次。
- 捕获范围最小、异常类型具体；捕获后恢复、转换为明确错误或重新抛出，不吞异常、不静默逐项跳过。最外层未知异常处理记录上下文、真实失败状态并传播/终止。
- 职责/docstring、WHY 注释与复杂度按 [engineering-quality.md](../engineering-quality.md)；说明真实契约与非显然约束，不复述代码、堆砌多行模板或写实现过程流水账。

## B09 — 迁移与验证

- 模型变更核对迁移依赖、历史数据、约束/索引和安装/升级路径；已执行迁移采用增量。数据 migration 使用历史模型/app registry，不导入未来业务模型。
- 大表变更评估锁表、分批回填、默认值、NULL/唯一性、重跑和回滚；只对实际交付支持的 DB 声称兼容，不从 SQLite/单库外推。
- 覆盖缺字段/非法值、空集/分页、不存在/已删、无权限/隔离、并发/幂等、异常与部分失败；批量写/软删除核对操作人、时间与历史引用。
- 分开说明 DB、缓存、队列、鉴权与外部调用的真实路径和替身边界；SQLite 或跳过 migration 不证明生产迁移、行锁或约束有效。
- 命令及运行配置从项目 settings/当前配置解析，记录实际结果和未验证项，不因规范采用而执行环境变更。
